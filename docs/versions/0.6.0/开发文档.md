**范围**：开发约定、框架与目录、业务模块划分、与 PRD 的对应关系及后续实现要点。

## 0. 工程版本与文档迭代约定

### 0.1 版本号与文档的对应关系

- **单一来源**：仓库根目录 `package.json` 的 `version` 字段为**工程语义化版本号**（如 `0.6.0`）。
- **清单**：`docs/version-manifest.json` 记录当前版本、上一版本（若有）及 `docs/` 下各文件与版本的关联；迭代文档或发版时请一并更新该文件。
- **按版本快照**：`docs/versions/`（按需）用于存放已发布版本的文档快照，流程说明见 [versions/README.md](./versions/README.md)。

### 0.2 版本迭代时如何查阅文档

每次做**版本迭代**（需求评审、架构调整、实现与联调、发版说明）时，应**同时对照**以下两类材料：

1. **当前版本**：`docs/` 目录下现行文档（及 `version-manifest.json` 中 `currentVersion`）。
2. **上一版本**：`version-manifest.json` 中的 `previousVersion` 非空时，以 `docs/versions/<previousVersion>/` 中的快照为准；若无快照，则以 Git 中该版本标签或分支上的 `docs/` 为准。

> 自 0.5 起，「服务端同步、登录、扩展端」语义已下线。自 0.6 起**产品主线为文件管理**（`fs_*`）；笔记 / 站点 / 项目文档 / 项目 / 云盘为**冻结模块**，勿再对其做功能迭代。

### 0.3 面向 AI / 自动化工具的定位

仓库根目录 `AGENTS.md` 索引了：

1. `docs/version-manifest.json`：版本号与文件列表事实源；
2. `docs/versions/<版本>/` 快照：用于做逐文件 diff；
3. `.cursor/rules/`：Cursor 内的默认提示词（页面分层、性能、Zustand、API 等）。

## 1. 仓库结构（Monorepo）

根目录 `package.json` 通过 npm/pnpm workspaces 管理 `packages/*` 与 `apps/*`。

| 路径 | 包名 | 职责 |
| --- | --- | --- |
| `packages/shared` | `@my-notes/shared` | 跨端共享类型、常量、纯函数（`createId`、Markdown 凭证镜像辅助等）。已删除一切「同步 / 冲突合并」纯函数。 |
| `packages/local-db` | `@my-notes/local-db` | Dexie 定义（`NotesDB`、单例 `db`、常量 `NOTES_DB_NAME → my_notes_v2`）；`version(1)` 旧表 + `version(2)` 增加 `fs_folders` / `fs_files`；提供 `ensureDefaultFolder`、`ensureSiteSpace`、`propagateSiteProjectToItems`。 |
| `apps/web` | `@my-notes/web` | Web 主应用：Vite + React + React Router；本地库来自 `@my-notes/local-db`。 |
| `apps/desktop` | `@my-notes/desktop` | Electron 桌面壳：主进程 + preload，运行时加载 `apps/web/dist`；构建 Windows `.exe`。 |

> 0.5 已下线：`apps/api`、`apps/extension`、`packages/sync-client`（历史代码在备份分支保留）。

### 1.1 常用脚本（根目录）

| 命令 | 说明 |
| --- | --- |
| `pnpm dev` | 启动 Web 开发服务（`@my-notes/web`）。 |
| `pnpm dev:desktop` | 并行启动 Web Vite + Electron（详见 `apps/desktop/scripts/dev.cjs`）。 |
| `pnpm build` | 构建 `shared` / `local-db` / `web`。 |
| `pnpm build:desktop` | 构建 web 产物 + Electron 主进程脚本。 |
| `pnpm lint` | 透传到 `@my-notes/web --if-present`。 |

### 1.2 Node / 包管理器约定

- **Node**：`>= 20`（见根 `package.json` `engines`）。
- **包管理器**：pnpm（仓库带 `pnpm-workspace.yaml`）。`@my-notes/shared`、`@my-notes/local-db` 直接以 `src/` 入口，避免预构建。

## 2. 技术栈

### 2.1 Web（`apps/web`）

- **构建**：Vite 7 + TypeScript（严格模式）；alias `@`→`src`，`@my-notes/shared`、`@my-notes/local-db`→各自 `src/index.ts`。
- **UI**：React 19 + Ant Design v6 + Tailwind CSS v4；入口 `main.tsx` 使用 `ConfigProvider` + `locale={zh_CN}`，并以 `<App>` 包裹路由以启用 `App.useApp()`。
- **路由**：`react-router-dom` v7 + `react-router-dom` Data Router；路由表统一在 `src/router/routes.tsx`，页面懒加载。
- **本地数据**：Dexie（`@my-notes/local-db`）；`useLiveQuery` 提供实时订阅。
- **样式约定**：见 `.cursor/rules/styling.rule.mdc`（Tailwind + CSS Modules + Less + AntD theme token）。
- **页面分层**：「页面入口 / 区域组件 / 业务 Hooks / 纯展示」四层，详见 `.cursor/rules/page-layering.rule.mdc`。

### 2.2 桌面端（`apps/desktop`）

- **运行时**：Electron 33。主进程 / preload 由 `tsc -p tsconfig.json` 编译到 `dist/main.js`、`dist/preload.js`。
- **渲染层**：直接加载 `apps/web/dist/index.html`（开发时回退到 Vite dev server）。
- **打包**：`electron-builder` 25；Windows 目标产出 NSIS 安装包 + Portable 单文件；macOS / Linux 仅作调试。
- **资源装载**：`apps/web/dist/**` 由 `extraResources.from = "../web/dist"` 拷到 `process.resourcesPath/web/`，主进程读 `path.join(process.resourcesPath, "web", "index.html")`。

### 2.3 共享包（`packages/shared`）

- 导出 `NoteRecord / ImageRecord / SnippetRecord / SiteSpaceRecord / ClipRecord / ProjectRecord`、`SnippetType`、`SNIPPET_TYPE_LABELS`、`createId`、Markdown 凭证镜像相关纯函数。
- **文本差异**（`text-diff.ts`）：`computeTextDiff` / `applyHunkResolutions` / `formatUnifiedDiff`；底层为 jsdiff（`packages/shared/vendor/diff`，Myers）产出类 git hunk（context/delete/add）；供 DiffLab 与后续导入 / 同步复用。无 React 依赖。
- **已删除**：`SyncStatus`、`SYNC_STATUS_LABELS`、`SiteSyncOptions` 等同步语义；`hasNoteConflict / decideNotePull / ...` 等冲突判定函数；`sync-common / sync-pull-pure / sync-site-pure / sync-drive-pure`。

### 2.4 本地数据库（`packages/local-db`）

- 单例 `db: NotesDB`；常量 `NOTES_DB_NAME = "my_notes_v2"`。
- `version(1)`：`folders / notes / images / snippets / site_spaces / clips / projects / sites / site_items / drive_folders / drive_files / blobs`。
- `version(2)`：新增 `fs_folders`（`id, parentId, name, createdAt, updatedAt`）、`fs_files`（`id, folderId, name, kind, createdAt, updatedAt`）；文本正文存 `contentText`。
- **已删除**：`drive_file_tombstones`（云端删除墓碑）。

## 3. 开发约定

### 3.1 TypeScript

- 严格模式 + `noUnusedLocals` + `noUnusedParameters` + `verbatimModuleSyntax`。
- 类型优先 `type`；只有「接口继承 / 声明合并」场景才用 `interface`。
- 禁止 `any`；用 `unknown` + 类型守卫。
- 路径别名：Web 端使用 `@/` 指向 `src/`。

### 3.2 页面分层与性能

- 详见 `.cursor/rules/page-layering.rule.mdc`、`.cursor/rules/react-performance.rule.mdc`。
- **纯展示组件必须 `memo`** 且使用具名函数；传给 memo 子组件的回调必须 `useCallback`。
- **业务 Hook** 与「UI 布局」解耦；只暴露 `state + actions`。
- 页面入口仅做 *组合与传递*；大段渲染下沉到区域组件 / 纯展示。

### 3.3 数据访问

- 所有数据访问走 `@my-notes/local-db` 的 `db` 单例。
- 跨表多次写入需 `db.transaction("rw", ...)` 包裹保持一致性。
- 时间戳统一 `Date.now()` 数字毫秒；不引入 `dayjs/moment` 持久化对象。

### 3.4 状态管理（Zustand）

- 当前没有跨页面共享的全局状态；`src/stores/` 暂空。
- 若新增全局 Store，请遵循 `.cursor/rules/zustand-stores.rule.mdc`（一文件一域、`useXxxStore` 命名、selector 精确订阅、不写异步、不嵌组件）。

### 3.5 API 请求层

- 当前不再使用 axios / fetch 访问任何后端；`src/services/` 仅保留 `siteProjectBackup`（纯文件 JSON 导出 / 导入）。
- 若未来恢复 API，必须遵循 `.cursor/rules/api-services.rule.mdc`：Axios 实例 + 按域拆分 `services/modules/xxx.ts`、组件 / Hook 中禁止直接 `fetch`。

### 3.6 安全与隐私

- 桌面端 `BrowserWindow` 强制 `contextIsolation: true`、`nodeIntegration: false`。
- 主进程 `setWindowOpenHandler` + `will-navigate` 拦截，所有外链 / 跨域跳转交给系统浏览器。
- 数据完全本地化，不会发起任何到远端的 HTTP 请求。

## 5. 桌面端要点

详细操作见 [`apps/desktop/README.md`](../apps/desktop/README.md)。要点：

- `apps/desktop/electron/main.ts` 作为主进程入口：单实例锁、托盘、应用菜单、全局快捷键、外链拦截、加载 web 静态资源。
- `apps/desktop/electron/preload.ts` 仅暴露 `__MY_NOTES_DESKTOP__` 标识，预留未来桌面端能力开关。
- 启动模式：
  - **开发**：`pnpm --filter @my-notes/desktop dev`（脚本会先拉起 Web Vite，再 `tsc + electron .`）。
  - **打包**：`pnpm --filter @my-notes/desktop dist:win`，产物在 `apps/desktop/release/`。

## 6. 文件级数据迁移（导出 / 导入）

- 入口：用户信息页 `/user` 的「导出 JSON / 导入 JSON」。
- 实现：
  - 导出：`apps/web/src/services/siteProjectBackup/exportPayload.ts` 收集 `projects + sites + site_items`，按结构化方式打包。
  - 导入：`applyImport.ts` 按「项目名 / 站点名+地址 / 条目名+正文」三级去重合并写回 IndexedDB。
- 文件结构版本：`formatVersion: 1`（见 `services/siteProjectBackup/types.ts`）。
