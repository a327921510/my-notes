# 产品需求文档（PRD）

**项目名称**：My Notes  
**版本**：V0.6（文件管理主线 + `.rm` 定制类型）  
**文档状态**：评审稿  
**日期**：2026-07-15

---

## 1. 产品背景与定位

用户在本地需要以**传统文件管理器**方式组织 Markdown 文档，并对「项目 README / 凭证表」类文档需要专用渲染与复制体验；同时关注隐私的用户希望**数据全部留在本地**、不依赖任何云端服务。

本期把 My Notes 主线收敛为 **纯本地优先的文件管理工具**：

- 核心交互为多级目录树 + `.md` / `.rm` 文件编辑；
- 数据存储于浏览器 / 桌面端的 IndexedDB；
- 跨设备迁移：旧模块仍可通过「文件导出 / 导入（JSON）」迁移；`fs_*` 导出扩展为后续项；
- 提供 Windows 桌面客户端（基于 Electron），界面复用 Web 端。

历史模块（笔记区、站点信息区、项目文档、项目信息区、云盘）**本期冻结**：可继续访问与展示，**不再迭代功能**，未来将废弃。

---

## 2. 产品目标

### 2.1 核心目标

- **文件管理主线**：多级目录树 CRUD；创建并编辑 `.md` / `.rm`。
- **`.rm` 定制类型**：继承原「项目文档」Markdown 特殊表格规则（凭证表 / 代码仓库表），阅读态专用渲染 + 一键复制；**不再**镜像到站点条目。
- **本地优先 + 离线可用**：所有 CRUD 不依赖网络。
- **桌面化体验**：沿用 V0.5 桌面端能力（窗口、托盘、全局快捷键等）。
- **统一界面**：桌面端 100% 复用 Web 端构建产物。

### 2.2 MVP 成功标准

- 打开应用默认进入文件管理；可建多级目录与 `.md` / `.rm`，刷新后数据仍在。
- `.rm` 凭证表 / 代码仓库表在阅读态正确渲染且可复制；站点信息区**不会**因此新增镜像条目。
- 五个冻结业务页仍可打开。
- 桌面端既有窗口 / 托盘 / 快捷键行为不回归。

---

## 3. 产品范围

### 3.1 本期范围（In Scope）

- Web / 桌面共用：**文件管理**（`/files`）、**差异测试**（`/diff-lab`）、用户信息（导出 / 导入，契约不变）、冻结业务页的只读可用性。
- IndexedDB 新表 `fs_folders` / `fs_files`（Dexie schema `version(2)`）。
- 桌面端壳沿用既有实现。
- 共享包文本差异 API（`computeTextDiff` / `applyHunkResolutions`），供测试页与后续导入 / 同步使用。

### 3.2 非本期范围（Out of Scope）

- 远端账号、登录、同步、冲突合并、浏览器扩展。
- 将旧笔记 / 云盘数据迁移进 `fs_*`。
- `fs_*` 纳入用户页 JSON 导出 / 导入。
- 拖拽移动、二进制上传、多选、全局搜索纳入 `fs_*`。
- 删除或改造冻结业务页的功能代码。

## 4. 关键概念

| 概念 | 说明 |
| --- | --- |
| 文件管理 | 类似传统资源管理器的多级目录树；节点为文件夹与文本文件（`.md` / `.rm`）。 |
| `.md` 文件 | 普通 Markdown；源码编辑 + 常规预览。 |
| `.rm` 文件 | README 定制类型（ReadMe 缩写）；Markdown 源码 + 特殊表格阅读渲染（凭证表 / 代码仓库表 / 通用 GFM 表），**不做站点镜像**。 |
| 文本差异比对 | 行级类 git unified diff（hunk + context/delete/add）；按 hunk 人工裁决（保留左 / 右 / 编辑）生成合并文本。后续本地导入与远端同步将复用同一套纯函数。 |
| 冻结模块 | 笔记区、站点信息区、项目文档、项目信息区、云盘：可展示，不再改动；计划后续废弃。 |
| 导出 / 导入 | 仍仅覆盖项目 / 站点 / 条目 JSON（历史契约）；`fs_*` 迁移后续再做。 |

## 5. 功能需求

### 5.1 Web 端 / 桌面端共用功能

#### 5.1.1 文件管理（`/files`）— 主线

- 左侧多级文件夹 + 文件树；右侧文档编辑区。
- 文件夹：新建 / 重命名 / 删除（含有子文件夹或文件时不可删）。
- 文件：在指定目录（或根）新建 `.md` / `.rm`；重命名 / 删除；同级名称不重复；文件名非法字符校验。
- `.md`：`@uiw/react-md-editor` 源码编辑 + 普通预览。
- `.rm`：同源码编辑；阅读态按特殊表头规则渲染表格并支持单元格一键复制；提供「查看示例」说明。
- 默认路由：`/` → `/files`。

#### 5.1.1b 差异测试（`/diff-lab`）

- 比对左右两段文本（可从文件管理选 `.md` / `.rm`，或直接粘贴）。
- 左 = base（本地 / 旧），右 = incoming（导入 / 远端语义）。
- 产出类 git hunk；支持 Unified / 并排审阅。
- 按 hunk 裁决：保留左 / 保留右 / 手工编辑；可一键全部保留左或右。
- 展示合并结果预览并支持复制；**本期不落库、不接入真实导入 / 同步**（能力预留给后续）。

#### 5.1.2～5.1.6 冻结模块（展示，不迭代）

以下页面保留路由与现有能力，**禁止在本迭代继续改动业务逻辑**：

| 模块 | 路径 | 说明（现状快照） |
| --- | --- | --- |
| 笔记区 | `/notes` | 文件夹 + 富文本笔记 |
| 站点信息区 | `/sites` | 站点 / 条目 |
| 项目文档 | `/project-markdown` | 项目 Markdown + 凭证镜像（历史能力） |
| 项目信息区 | `/projects` | 项目聚合视图 |
| 云盘工作台 | `/cloud-drive` | 本地目录 + blob |

#### 5.1.7 用户信息与数据迁移（`/user`）

- 本地账户；导出 / 导入项目 + 站点 + 条目 JSON（契约不变，**不含** `fs_*`）。

#### 5.1.8 全局搜索

- 沿用既有：笔记 / 站点条目 / 项目条目（**不含** `fs_*`，后续再扩）。

## 6. 数据模型（IndexedDB）

| 表 | 主要字段 |
| --- | --- |
| `fs_folders` | `id, name, parentId, createdAt, updatedAt` |
| `fs_files` | `id, folderId, name, kind ('md'\|'rm'), contentText, createdAt, updatedAt` |
| （冻结）`folders` / `notes` / … / `drive_*` / `projects` / `sites` / `site_items` / `blobs` 等 | 保持 V0.5 不变 |

**约定**：

- `fs_folders.parentId` / `fs_files.folderId` 为 `null` 表示根级。
- 文件 `kind` 由扩展名推导：`.md` → `md`，`.rm` → `rm`；创建时强制后缀。
- Dexie：`version(1)` 保留旧表；**`version(2)`** 增加 `fs_*`。库名仍为 `NOTES_DB_NAME`（`my_notes_v2`）。

## 7. 业务流程

### 7.1 文件管理编辑

1. 用户进入文件管理；
2. 建目录 / 建 `.md` 或 `.rm`；
3. 编辑正文，防抖写入 `fs_files.contentText`；
4. `useLiveQuery` 刷新树与编辑区。

### 7.2 文件级数据迁移（旧数据）

与 V0.5 相同：用户信息页导出 / 导入站点与项目 JSON。

### 7.3 桌面端启动

与 V0.5 相同。

---

## 8. 非功能需求

- **性能**：数千级目录 / 文件节点下列表可用。
- **可用性**：核心操作 1～2 步可达。
- **隐私**：数据完全本地，不向远端发送内容。
- **跨端一致性**：Web 与桌面端 UI 一致。

---

## 9. 风险与应对

- **本地数据丢失**：引导定期导出（当前导出尚不含 `fs_*`，需尽快补齐或用户自行备份策略提示）。
- **双体系并存**：冻结模块与 `fs_*` 并存一段时间，避免误改冻结页。
- **桌面端打包平台依赖**：Windows `.exe` 须在 Windows 或具备 wine 的 CI 上 `dist:win`。
