## 0. 版本与文档约定

### 0.1 版本号

- **单一来源**：根目录 `package.json` 的 `version` 字段即工程语义化版本号。
- **清单**：`docs/version-manifest.json` 记录当前版本、上一版本与 `docs/` 下的文件清单；改文档或发版时一并更新。
- **快照**：`docs/versions/<版本号>/` 存放升版前冻结的文档快照，流程见 [versions/README.md](./versions/README.md)。

### 0.2 需求落地约定

- **文档是需求的最终归口**：无论需求来自对话、工单还是口头，成型后都要汇总进 `docs/`；实现与评审以仓库内文档为准。
- **主动识别升版**：涉及对外行为、数据格式、接口契约、导出格式、兼容性或验收标准的实质变化时，需提示是否升版；破坏性变更升 MAJOR/MINOR。
- **`1.0.0` 是新基线**：本次重构作废了全部历史需求，不存在可对照的"上一版"，`previousVersion` 为空属正常状态。

## 1. 工程结构

### 1.1 Monorepo（pnpm workspaces）

`pnpm-workspace.yaml` 定义工作区：`apps/*`、`packages/*`。

| 路径 | 包名 | 职责 |
| --- | --- | --- |
| `apps/api` | `@my-notes/api` | 后端：Fastify + SQLite（Drizzle）；账号、云盘节点、文件对象、`.mmd` 正文、导入导出 |
| `apps/web` | `@my-notes/web` | 前端：Vite + React + React Router + Ant Design；云盘工作台与文档页 |
| `apps/desktop` | `@my-notes/desktop` | **新增**：Electron 壳；加载 `apps/web` 产物，提供原生文件对话框与窗口菜单 |
| `packages/shared` | `@my-notes/shared` | 跨端共享的类型、常量与**纯函数**（命名校验、路径与大小格式化、同名去重、`.mmd` 分段解析、`.mmd` 逐行文本差异） |

**已删除的包**：`packages/local-db`（Dexie 本地业务库）、`packages/sync-client`（推送 / 拉取同步）、`apps/extension`（浏览器扩展）——均随旧需求作废，见 §7。

### 1.2 常用脚本（根目录）

| 脚本 | 作用 |
| --- | --- |
| `pnpm dev` | 启动 Web 开发服务（`@my-notes/web`） |
| `pnpm dev:api` | 启动后端（`@my-notes/api`） |
| `pnpm dev:desktop` | 启动 Electron 开发态（加载 Web dev server） |
| `pnpm build` | 依次构建 shared、api、web、desktop |

**约定**：Node `>= 20`（根 `package.json` `engines`）。Web 端仅本地启动用于验证，不做服务器部署。

## 2. 目标架构

### 2.1 分层与数据流

```
┌───────────────────────────┐   ┌───────────────────────────┐
│  apps/desktop (Electron)  │   │  apps/web (浏览器, 本地)   │
│  · 加载同一 React 应用     │   │  · 同一 React 应用         │
│  · 原生文件对话框 (IPC)    │   │  · 浏览器下载 / 文件选择   │
└─────────────┬─────────────┘   └─────────────┬─────────────┘
              │        HTTP + JWT（Axios）     │
              └───────────────┬────────────────┘
                              ▼
                  ┌───────────────────────┐
                  │   apps/api (Fastify)  │  ← 唯一事实来源
                  │  鉴权 / 节点树 / 文件  │
                  └───────┬───────┬───────┘
                          ▼       ▼
                 SQLite(Drizzle)  磁盘对象存储
                 users            uploads/<userId>/<storageId>
                 drive_nodes
                 storage_objects
                          ▲
                          │ 类型与纯函数
                  ┌───────┴────────┐
                  │ packages/shared│
                  └────────────────┘
```

### 2.2 服务端权威（关键约束）

- 客户端**不持有业务数据副本**：无 IndexedDB 业务库、无本地节点表、无同步状态字段、无冲突合并、无删除墓碑。
- 所有读写都是在线请求；成功即生效，失败即回滚 UI 并提示。
- 客户端只缓存：JWT 与用户摘要（持久化）、目录树与列表的请求缓存、上传队列、编辑器草稿（内存，登出即清）。
- **唯一的版本比较**发生在 `.mmd` 保存链路：仅在内存中对"编辑器当前内容"与"服务端当前正文"两者做逐行 diff 供用户决策（链路见 §4.4，需求见 PRD §7.3.5）。它不引入本地副本，也不改变上述结论。

### 2.3 技术栈

| 层 | 选型 |
| --- | --- |
| 后端 | Fastify 5、`@fastify/jwt`、`@fastify/multipart`、`@fastify/cors`、Drizzle ORM + `better-sqlite3`、`bcrypt`、`fflate`（ZIP 读写） |
| Web | Vite 6、TypeScript（严格模式）、React 19、React Router 7（`createBrowserRouter`）、Ant Design 6 + `@ant-design/icons`、Tailwind CSS 4（布局补充）、Zustand（会话）、Axios（请求层） |
| 桌面端 | Electron（main + preload + `contextBridge` IPC）、加载 Web 产物 |
| 共享 | 纯 TypeScript，无运行时依赖 |

## 3. 数据模型（服务端）

SQLite + Drizzle，schema 定义在 `apps/api/src/db/schema.ts`。

### 3.1 `users`

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | text PK | UUID |
| `email` | text | 原始输入的邮箱 |
| `email_normalized` | text | 小写去空格；**唯一索引** |
| `password_hash` | text | bcrypt |
| `created_at` / `updated_at` | integer | 毫秒时间戳 |

### 3.2 `drive_nodes`（目录与文件统一节点表）

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | text PK | UUID |
| `user_id` | text | **隔离键**，所有查询的强制条件 |
| `parent_id` | text nullable | 父节点；`null` 表示根节点（每账号唯一） |
| `kind` | text | `folder` \| `file` |
| `name` | text | 展示名（保留用户输入的大小写） |
| `name_key` | text | 归一化名（去首尾空格 + 转小写），用于同级唯一 |
| `mime_type` | text nullable | 文件 MIME |
| `size_bytes` | integer | 文件字节数；目录为 `0` |
| `checksum` | text nullable | 文件 SHA-256 |
| `storage_id` | text nullable | 指向 `storage_objects`；目录为空 |
| `doc_kind` | text nullable | `mmd` 表示 `.mmd` 文档；其他为空 |
| `created_at` / `updated_at` | integer | 毫秒时间戳 |

**索引与约束**

- 唯一索引 `(user_id, parent_id, name_key)` —— 同级同名的硬约束，前端校验只是体验优化。
- 普通索引 `(user_id, parent_id)` —— 列目录。
- 普通索引 `(user_id, name_key)` —— 按名称搜索。
- 根节点：`parent_id IS NULL AND kind = 'folder'`，每个 `user_id` 有且仅有一个，注册时幂等创建。
- 删除目录时递归删除子孙节点并释放其存储对象（服务端在单事务内完成）。

### 3.3 `storage_objects`

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `storage_id` | text PK | 落盘对象标识 |
| `user_id` | text | 归属账号，下载鉴权用 |
| `size_bytes` | integer | 字节数 |
| `checksum` | text | SHA-256 |
| `created_at` | integer | 毫秒时间戳 |

- 落盘路径：`apps/api/uploads/<userId>/<storageId>`；部署时需持久化卷与目录权限。
- 不做内容去重（相同 checksum 也各存一份），去重列为后续优化。
- `.mmd` 正文即其存储对象内容，不单独建表。

### 3.4 用量统计

`SUM(size_bytes) WHERE user_id = ? AND kind = 'file'`；配额与单文件上限来自环境变量（§6）。

## 4. 接口契约

### 4.1 通用约定

| 项 | 约定 |
| --- | --- |
| 基址 | `/api`；Web 开发态由 Vite 代理到后端；桌面端使用绝对基址（`VITE_API_BASE`） |
| 鉴权 | 除 `POST /api/auth/register`、`POST /api/auth/login` 外全部需要 `Authorization: Bearer <jwt>` |
| 隔离 | `userId` **只**从 JWT 解析，绝不接受请求体或查询参数传入 |
| 越权 | 访问非本账号节点统一返回 `404`，不区分"不存在"与"无权限" |
| 时间 | 一律毫秒时间戳（integer） |
| 错误体 | `{ code: string, message: string, details?: unknown }`；`message` 为可直接展示的中文 |

**业务错误码**

| code | HTTP | 含义 |
| --- | --- | --- |
| `AUTH_EMAIL_TAKEN` | 409 | 邮箱已注册 |
| `AUTH_INVALID_CREDENTIALS` | 401 | 邮箱或密码不正确 |
| `AUTH_TOKEN_EXPIRED` | 401 | 会话过期，需重新登录 |
| `NODE_NOT_FOUND` | 404 | 节点不存在或不属于当前账号 |
| `NODE_NAME_INVALID` | 400 | 名称违反命名约束（PRD §7.2.6 第 1～3 条） |
| `NODE_NAME_CONFLICT` | 409 | 同级同名；`details` 含冲突节点名，前端据此弹同名策略 |
| `NODE_MOVE_INTO_SELF` | 400 | 目录被移动到自身或其子孙 |
| `NODE_ROOT_IMMUTABLE` | 400 | 根目录不可重命名 / 删除 / 移动 |
| `FILE_TOO_LARGE` | 413 | 超过单文件上限 |
| `QUOTA_EXCEEDED` | 507 | 超过账号存储配额 |
| `DOC_NOT_MMD` | 400 | 对非 `.mmd` 节点调用文档接口 |
| `DOC_STALE` | 409 | 保存时基版本已过期（服务端 `updatedAt` 已变化）；`details` 含服务端最新 `updatedAt`，前端据此拉取服务端正文进入差异对比 |
| `ARCHIVE_INVALID` | 400 | 导入包无法解析 |

### 4.2 账号

| 方法 | 路径 | 请求 | 响应 |
| --- | --- | --- | --- |
| POST | `/api/auth/register` | `{ email, password }`（密码 ≥ 8 位） | `{ token, user }`，并幂等创建根目录 |
| POST | `/api/auth/login` | `{ email, password }` | `{ token, user }` |
| GET | `/api/auth/me` | — | `{ user }`（邮箱、注册时间） |
| POST | `/api/auth/password` | `{ currentPassword, newPassword }` | `204`；旧 token 失效 |

`user`：`{ id, email, createdAt }`。

### 4.3 云盘节点

| 方法 | 路径 | 请求 | 响应 |
| --- | --- | --- | --- |
| GET | `/api/drive/nodes` | query `parentId?`（缺省为根）、`sort`（`name`/`size`/`updatedAt`）、`order`（`asc`/`desc`） | `{ parent, nodes[] }`；目录排在文件之前 |
| GET | `/api/drive/nodes/:id` | — | `{ node }` |
| GET | `/api/drive/nodes/:id/path` | — | `{ path: NodeBrief[] }`（根 → 自身，用于面包屑） |
| GET | `/api/drive/search` | query `keyword`、`limit`、`offset` | `{ items: (Node & { path })[] , total }`；仅按名称匹配 |
| POST | `/api/drive/folders` | `{ parentId, name }` | `{ node }` |
| POST | `/api/drive/files` | multipart：`parentId`、`onConflict`、`file` | `{ node }` |
| PATCH | `/api/drive/nodes/:id` | `{ name }` | `{ node }` |
| POST | `/api/drive/nodes/move` | `{ ids[], targetParentId, onConflict }` | `{ moved[], skipped[], failed[] }` |
| POST | `/api/drive/nodes/delete` | `{ ids[] }` | `{ deleted[], failed[] }`；目录递归删除 |
| GET | `/api/drive/nodes/:id/download` | — | 文件流（`Content-Disposition` 带节点名） |
| GET | `/api/drive/usage` | — | `{ usedBytes, quotaBytes, fileCount, folderCount, maxFileSizeBytes }` |

`onConflict`：`rename` \| `overwrite` \| `skip`，缺省 `rename`。

### 4.4 `.mmd` 文档

| 方法 | 路径 | 请求 | 响应 |
| --- | --- | --- | --- |
| POST | `/api/docs` | `{ parentId, name, content? }`（`name` 自动补 `.mmd`） | `{ node }` |
| GET | `/api/docs/:id` | — | `{ node, content }`（UTF-8 文本） |
| PUT | `/api/docs/:id` | `{ content, baseUpdatedAt? }` | `{ node }`；传了 `baseUpdatedAt` 且与服务端不一致时返回 `DOC_STALE` |

**差异对比链路（PRD §7.3.5）无专用接口**，差异计算在客户端完成：

1. 打开文档：`GET /api/docs/:id` → 记住 `node.updatedAt` 作为**基版本**。
2. 保存：`PUT /api/docs/:id` 携带 `baseUpdatedAt`。
3. 返回 `DOC_STALE` → 再次 `GET /api/docs/:id` 取服务端正文 → 用 `diffLines`（`@my-notes/shared`）在客户端算逐行差异并展示。
4. 用户选「用本机版本覆盖」→ 用刚取回的 `updatedAt` 作为新基版本重试 `PUT`（服务端不提供跳过校验的强制写入参数，避免绕过对比）。
5. 用户选「采用服务端版本」→ 仅替换编辑器内容与基版本，不发写请求。

### 4.5 导入 / 导出

| 方法 | 路径 | 请求 | 响应 |
| --- | --- | --- | --- |
| POST | `/api/drive/export` | `{ ids[] }`（多选）或 `{ folderId }`（整目录，缺省为根） | ZIP 流；目录嵌套 + 根部 `.mydrive-manifest.json` |
| POST | `/api/drive/import/preflight` | multipart：`archive` | `{ folderCount, fileCount, totalBytes, conflicts[], quotaOk }` |
| POST | `/api/drive/import` | multipart：`archive`、`targetParentId`、`onConflict` | `{ createdFolders, createdFiles, skipped[], failed[] }` |

**导出包格式**

```
export-<yyyyMMdd-HHmm>.zip
├── .mydrive-manifest.json
├── 工作/
│   ├── 项目A/
│   │   ├── 说明.mmd
│   │   └── 合同.pdf
│   └── 备注.mmd
└── 图片.png
```

`.mydrive-manifest.json`：

```json
{
  "manifestVersion": 1,
  "exportedAt": 1757000000000,
  "account": "user@example.com",
  "entries": [
    {
      "path": "工作/项目A/说明.mmd",
      "kind": "file",
      "sizeBytes": 1024,
      "mimeType": "text/markdown",
      "docKind": "mmd",
      "checksum": "sha256:...",
      "createdAt": 1756900000000,
      "updatedAt": 1756990000000
    }
  ]
}
```

- 导入时清单缺失即按外部普通 ZIP 处理：只依据目录结构还原，MIME 按扩展名推断，时间戳取导入时间。
- 清单存在但某条目 checksum 不匹配时，进入 `failed[]` 并附原因，由用户选择跳过或强制导入。

**其他规则**：纯展示组件必须 `memo` 包裹并配合 `useCallback`；Props 类型命名 `<ComponentName>Props` 并 `export`；请求一律走 `services/request.ts`，禁止在组件内直接 `fetch`/`axios`。

### 5.3 流程地图（stage 命名）

编排入口顶部按 `std-comments` 写流程地图；stage 名同时用于块注释、日志字段与 E2E 定位属性 `data-testid="{feature}.{stage}"`。

| 能力 | 入口 | stage 1→N |
| --- | --- | --- |
| 上传文件 | `useDriveTransfer.uploadFiles` | `pickFiles` → `validateFiles` → `resolveConflict` → `uploadQueue` → `refreshList` |
| 批量移动 | `useDriveMutations.moveNodes` | `collectSelection` → `pickTarget` → `validateTarget` → `applyMove` → `refreshTree` |
| 删除节点 | `useDriveMutations.deleteNodes` | `collectSelection` → `confirmDanger` → `applyDelete` → `refreshList` |
| 保存文档 | `useMmdDocument.saveDocument` | `guardDirty` → `checkStale` → `resolveDiff`（无差异或基版本未过期则跳过） → `applySave` → `syncMeta` |
| 文档差异对比 | `useMmdDiff.compareWithServer` | `fetchServerDoc` → `computeDiff` → `renderDiff` → `resolveOutcome` |
| 导出 ZIP | `useDriveTransfer.exportArchive` | `collectSelection` → `requestArchive` → `saveArchive` |
| 导入 ZIP | `useDriveTransfer.importArchive` | `pickArchive` → `preflight` → `resolveConflict` → `applyImport` → `reportResult` |

### 5.4 会话与请求拦截

- 请求拦截器注入 `Authorization`；响应拦截器把后端 `code` 映射为中文提示。
- 收到 `401`（`AUTH_TOKEN_EXPIRED` 或无效 token）时：清空 `useAuthStore`、清空内存缓存、跳 `/login` 并带上来源路由。
- `NODE_NAME_CONFLICT` 不弹全局错误，由调用方接管以展示同名策略选择。

## 6. 配置与安全

| 环境变量 | 位置 | 说明 |
| --- | --- | --- |
| `JWT_SECRET` | api | JWT 签名密钥；**生产必填**，开发态可用占位 |
| `JWT_EXPIRES_IN` | api | 会话有效期，默认 `7d` |
| `DATABASE_FILE` | api | SQLite 文件路径，默认 `apps/api/data/app.db` |
| `UPLOAD_DIR` | api | 对象落盘目录，默认 `apps/api/uploads` |
| `MAX_FILE_SIZE_BYTES` | api | 单文件上限，默认 200MB（PRD §16-Q9） |
| `USER_QUOTA_BYTES` | api | 账号配额，默认 5GB |
| `VITE_API_BASE` | web / desktop | 后端绝对基址；Web 开发态可留空走 Vite 代理，桌面端必填 |

**安全要求**

- 密码仅以 bcrypt 摘要存储；不提供任何免密 / 演示登录旁路。
- 修改密码后旧会话必须失效（token 中携带 `passwordVersion`，与库中值不一致即拒绝）。
- 文件下载必须校验 `storage_objects.user_id` 与 token 中 `userId` 一致；不开放任何静态直链。
- `apps/api/data/` 与 `apps/api/uploads/` 不入版本库（已在 `.gitignore`）。

## 8. 桌面端（`apps/desktop`）

| 项 | 约定 |
| --- | --- |
| 结构 | `main.ts`（窗口与菜单）、`preload.ts`（`contextBridge` 暴露白名单 API）、无独立渲染层 |
| 加载内容 | 开发态加载 Web dev server URL；生产态加载 `apps/web` 构建产物 |
| 安全 | `contextIsolation: true`、`nodeIntegration: false`；渲染层只能通过 preload 白名单调用主进程 |
| 原生能力 | `selectDirectoryForImport()`、`selectSavePath(defaultName)`、`writeArchive(path, bytes)`；仅用于 PRD §7.4 的导入导出 |
| 后端地址 | 通过构建期 `VITE_API_BASE` 注入；不在渲染层硬编码 |
| 会话存储 | 复用 Web 的持久化会话；桌面端不额外落盘明文 token 之外的凭据 |

桌面端**不引入**任何 Web 端没有的业务功能——保证两端行为一致，仅文件对话框走原生。
