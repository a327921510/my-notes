# 需求台账（REQ Index）

> **每条需求一行**。详细说明可链到同目录下 `REQ-*.md` 或版本文档章节。  
> 工作流见已安装的 `req-workflow` skill（`WORKFLOW.md`）。  
> 模板：[\_template.md](./_template.md)

## 状态说明

`待评估` → `已评审`（完整功能）→ `待开发` → `开发中` → `联调中` → `待验收` → `已上线`  
旁路：`挂起` / `不做`

## 类型说明

| 类型 | 含义 |
|------|------|
| 优化 | 体验/文案/交互等小改，不新增主能力 |
| 小需求 | 小范围新能力，通常无需独立版本 PRD |
| BUG | 测试或线上缺陷 |
| 完整功能 | 评审后的较大迭代项，需版本功能/测试文档 |

## 填写约定

1. **REQ-ID**：`REQ-YYYYMMDD-序号`，同一天多条用 `01`、`02`…
2. **端**：使用 `req-workflow.local.mdc` 中的 repo label（多仓可写「多端」或列出多个 label）
3. **关联 commit**：优先 short hash；有 PR 则贴 URL；多仓用 `label: hash` 拼接
4. **完整功能**：可先占一行「迭代合集」指向版本 PRD，熟了再拆细
5. **工时**：0.5h 粒度；含沟通、联调、自测

## 月末统计（示例问法）

- 本月 `已上线` 行的 `实际(h)` 求和 → 交付工时
- 按 `类型` 筛选 → 优化/BUG/需求占比
- 按 `端` 筛选 → 各仓投入
